## AR-13【要検討】承認コンソールとしての App Refiner

[../ARCHITECTURE.md](../ARCHITECTURE.md) の構想では、App Refiner は
「スマホの Gemini ではできないことを補う、見て判断する場所」になります。

```
スマホの Gemini            ブラウザ（App Refiner）
─────────────            ──────────────────
「ここを直して」      →
                           差分を赤緑で表示
  MCP が提案             ←  [適用する] をタップ
                           プレビューで実物を確認
  push → 公開               依頼履歴・アプリ台帳
```

ただし **着手は MCP（`publish_custom_html` と改修系ツール）の完成後**です。
先に UI を作っても、表示するデータの出どころが無く、憶測で作ることになります。

現時点で言えるのは、既存の機能のうち次が残り、他は Gemini に話せば済むため
役割を終える見込み、ということだけです。

| 機能 | 見込み |
| --- | --- |
| アプリ台帳（一覧・プレビュー・メモ） | 残る |
| 依頼履歴（未対応の把握） | 残る。App Studio 側には無い独自の価値 |
| 要望入力（プリセット・種類・優先度） | Gemini に話せば済む |
| 指示書の生成とコピー | 同上。ただし MCP 完成までは主経路として現役 |

## AR-2 [高] プレビュー読み込み失敗時の見え方を改善

**症状**: 到達できない公開URLを登録すると、ブラウザのエラーページが iframe 内に読み込まれて
白い枠が表示されることがある。iframe の `load` イベントが発火してしまうため、
現在の「9秒タイムアウト → プレビュー不可」の判定に引っかからない。

**方針案**（いずれか、または組み合わせ）

1. プレビュー枠に手動リロードボタンを置く（タップで `mountPreview()` をやり直す）
2. 設定に「カードのプレビューを表示する」トグルを追加し、`localStorage` に保存する
   （通信量を抑えたい人・プレビューが邪魔な人向けにもなる）
3. プレビュー枠の下端に公開URLのラベルを常時重ねて、白い枠でも何のカードか分かるようにする

**制約**: 到達確認のための `fetch` は使わないこと（外部通信をしない方針のため）。

**完了条件**: `tests/smoke.mjs` に該当の検証項目を追加し、全項目 PASS。

## AR-9 [高] プレビューが相手ページの上端しか映っていない

**実測値**（iPhone 相当 390px 幅・スタイル適用状態で計測）:

| 項目 | 値 |
| --- | --- |
| プレビュー枠 | 356 × 112 px |
| 縮小率 | 0.913（iframe を 390px 幅で描画） |
| 実際に見えている相手ページの高さ | **上から 123 CSS px だけ** |

123px は多くのアプリでヘッダー1本分しかなく、「どんなアプリだったか」を思い出す役に立っていない。

**方針案**

1. カードの高さを `h-28`(112px) から 200px 前後に上げる（見える高さが約 220px になる）
2. または iframe の描画幅を 390px より広げて縮小率を下げる
   （例: 820px 幅で描画 → 縮小率 0.43 → 約 260px 分が見える。ただしタブレット相当のレイアウトになる）
3. プレビューを正方形に近い比率にして、カードのグリッド表示に寄せる

1 が最も素直。カード1枚が縦に長くなるので、一覧性とのバランスを見て決める。

**完了条件**: 実機で「どのアプリか」が判別できること。`tests/smoke.mjs` の計測値も更新する。

## AR-10 [中] CDN が読めないときのフォールバックCSSを内蔵

Tailwind CSS を CDN から読んでいるため、**CDN に到達できない環境ではアプリ全体が完全に無スタイル**になる
（実装中のサンドボックスで実際に発生。機能は動くが、見た目は素の HTML）。
オフラインや社内ネットワーク、CDN 障害時に同じことが起きる。

**方針案**: `<style>` に最小限のフォールバック（ダーク背景、文字色、ボタンの最低限の余白とタップ領域、
入力欄の枠線）を入れておく。Tailwind が読めればそちらが優先されるので共存できる。

**制約**: 単一ファイル構成は維持すること（インラインの `<style>` に書く）。
